# Cut Flow 生产工作流重构总文档

> 状态：执行中  
> 建立日期：2026-07-28  
> 用途：这是后续新对话、开发任务和验收的首要入口。开始工作前先阅读本文件，并在每次完成任务后更新“已实施”和“待实施”。

## 1. 产品重新定位

Cut Flow 不再以“替代 Premiere Pro 或剪映、完成最终成片”为目标。

新的产品定位是：

> 本地优先的 AI 视频前期生产与剪辑交付助手。

应用只专注以下能力：

1. 主题发现、筛选和立项。
2. 文案、脚本和分镜设计。
3. 图片、图形及必要素材的生成和管理。
4. 配音生成、时间对齐和字幕导出。
5. 静态封面设计与版本管理。
6. 使用 Remotion 生成简单数字、图片和解释型动效。
7. 将全部成果整理为可进入 Premiere Pro、剪映等软件的剪辑生产包。

复杂剪辑、精细关键帧、调色、蒙版跟踪、多机位、专业混音及最终包装交给专业剪辑软件。

## 2. 核心设计原则

- **生产包优先**：最终产品交付物是有序素材目录、脚本、分镜、配音、字幕、动效片段和剪辑说明，不只是一个 MP4。
- **音频决定时间**：最终分镜时长和字幕时间以实际配音或转录结果为准。
- **Remotion 是动效生成器**：用于粗剪预览和少量程序化动效，不继续扩展为完整非线性编辑器。
- **专业软件完成终剪**：内部项目格式保持稳定，PR/剪映适配作为可替换导出器。
- **标准格式优先**：优先输出 WAV、SRT、CSV、Markdown、PNG、MP4 和 JSON；不把非公开工程格式作为核心依赖。
- **向后兼容**：现有 `project.json`、预览和 MP4 渲染能力继续可用，采用渐进迁移。

## 3. 目标工作流

```text
主题选择
→ 资料与观点整理
→ 文案脚本
→ 配音生成或导入
→ 按真实音频校准时间
→ 分镜与素材需求
→ 素材生成、匹配和审核
→ 字幕处理
→ 封面设计
→ 简单 Remotion 动效
→ 粗剪预览
→ 剪辑生产包
→ Premiere Pro / 剪映终剪
```

## 5. 模块职责

| 模块 | 保留/调整后的职责 |
| --- | --- |
| Topic | 选题推荐、收藏、目标受众、平台和观点 |
| Content | 文案版本、结构检查、脚本段落 |
| Voice | 配音生成/导入、真实时长、词级时间戳 |
| Storyboard | 旁白到镜头的映射、素材需求、剪辑建议 |
| Assets | 生成、搜索、授权、复用和素材覆盖检查 |
| Motion | 数字、图表、图片分层、标题卡等简单片段 |
| Captions | SRT/ASS/TXT/JSON 输出与样式建议 |
| Covers | 封面画布、标题、候选版本和多尺寸导出 |
| Delivery | 生产包、粗剪预览和未来的时间线交换格式 |
| Remotion | 粗剪预览和独立动效片段渲染 |

## 6. 明确停止扩展的范围

- 不继续把现有时间线扩展为完整多轨 NLE。
- 不做专业调色、蒙版跟踪、视频抠像和多机位。
- 不做复杂关键帧曲线编辑器。
- 不把完整 AI 视频生成设为默认素材路线。
- 不优先生成或逆向维护剪映私有工程文件。
- 不在当前阶段实现自动发布、账号矩阵和云端协作。

现有编辑页暂时保留为“粗剪预览与检查”，后续逐步弱化“最终剪辑”表述。

## 7. 剪辑生产包规范

目标目录：

```text
项目标题-editing-package/
├── 00-project/
│   ├── manifest.json
│   ├── script.md
│   ├── storyboard.csv
│   └── editing-notes.md
├── 01-voice/
│   └── narration.wav
├── 02-captions/
│   └── captions.srt
├── 03-assets/
│   ├── shot-001-...
│   └── shot-002-...
├── 04-motion-clips/
├── 05-covers/
└── 06-preview/
```

第一阶段不强制每个目录都有文件，但目录和清单保持稳定。素材按分镜编号命名，清单记录原始相对路径，避免丢失来源关系。

## 10. 推荐实施顺序

1. 剪辑生产包生成与导出。
2. 配音真实时长和字幕多格式交付。
3. 素材槽位及覆盖检查。
4. 独立 Remotion 动效片段。
5. 封面设计。
6. 页面导航和文案收缩。
7. Premiere 时间线交换。

## 11. 每轮开发完成规则

每完成一轮必须：

1. 更新本文件第 8、9 节的复选框和说明。
2. 在“实施记录”追加日期、完成内容、验证结果和明确下一步。
3. 运行与改动相称的测试、类型检查和构建。
4. 不把尚未验证的能力标为完成。
5. 若改变产品边界，先更新本文件再写代码。
