# Cut Flow 开发计划

## 1. 计划原则

以“可运行的端到端闭环”排序，而不是按页面或技术名词堆功能。每个里程碑都必须产出可演示结果；AI、Electron 和复杂 UI 不得阻塞渲染内核。

## 2. 里程碑总览

| 里程碑                    | 目标                       | 主要交付物                             | 退出条件                     |
| ------------------------- | -------------------------- | -------------------------------------- | ---------------------------- |
| M0 工程基线               | 建立可持续开发的工作区     | pnpm、TS、lint、test、CI 基础          | 质量命令全部可运行           |
| M1 渲染闭环               | 从项目文件生成 MP4         | Schema、三镜头渲染、字幕、音频、转场   | demo MP4 实际导出并验收      |
| M2 可编辑工作流（已完成） | 非开发者可调整项目         | 项目/分镜卡片/预览/导出 UI             | 无需手改 JSON 完成示例视频   |
| M3 AI 内容链（已完成）    | 从主题生成脚本、配音和字幕 | 文本 Provider、TTS、转录对齐、缓存     | 主题到可预览视频闭环         |
| M4 素材与模板（已完成）   | 提高稳定性和账号辨识度     | 素材库、授权元数据、game-dev-log 模板  | 本地素材可匹配并局部替换     |
| M5 桌面交付（已完成）     | 提供本地桌面体验           | Electron、安全上下文、安装包、任务管理 | Windows 安装包完成端到端验收 |

## 3. 详细阶段

### M0：工程基线

任务：

1. 初始化 pnpm workspace、TypeScript strict、ESLint、Prettier、Vitest。
2. 建立 `core`、`renderer`、`media` 和 `studio` 最小包结构。
3. 配置根命令、共享 tsconfig 和基础 CI。
4. 明确 FFmpeg 检测方式、日志与错误类型。

交付物：可安装、可构建、可运行测试的空骨架。

验收：`pnpm typecheck && pnpm test && pnpm lint` 通过。

### M1：确定性视频渲染 MVP

任务按顺序执行：

1. `project.json` Zod Schema、版本字段和清晰错误格式。
2. 项目加载、跨平台路径解析、素材存在性校验。
3. 时间轴计算及秒/帧转换测试。
4. Remotion Root 与 Composition。
5. 图片/视频镜头组件和三种布局。
6. 五种基础 motion、整句字幕/淡入字幕和安全区。
7. `none`/`fade` 转场及本地旁白；旁白缺失时静音降级。
8. 三镜头 demo-project 和占位素材。
9. `validate`、`preview`、`render` 命令。
10. 实际导出 MP4，并用 ffprobe 与人工方式验收。

验收基线：1080×1920、30 FPS、H.264；有音频时 AAC；画面、字幕、动效及转场正确。

### M2：镜头卡片编辑器

任务：

1. 项目列表和新建/打开项目。
2. 分镜卡片的字幕、时长、布局、动效和素材编辑。
3. 卡片排序、锁定、自动保存和脏状态提示。
4. Remotion Player 预览、当前镜头属性和简化时间条。
5. 导出任务状态、进度、取消、失败重试和日志入口。

验收：用户不编辑 JSON，能替换素材、调整三个镜头并导出视频。

### M3：AI 脚本、TTS 与字幕对齐

任务：

1. 定义 Provider 接口、伪 Provider 和契约测试。
2. 脚本输入表单及严格 JSON 输出 Schema。
3. 结构修复、有限重试、字数和目标时长检查。
4. TTS 生成、音频时长探测和缓存。
5. 转录与句级/词级时间戳模型。
6. 按真实音频校准镜头时间，支持逐词高亮字幕。
7. API 密钥配置、取消、错误提示和费用边界。

验收：输入一个开发日志主题，可生成脚本、分镜、旁白和对齐字幕；失败步骤可单独重试。

### M4：素材与模板系统

任务：

1. 本地素材导入、缩略图和 ffprobe 元数据。
2. 来源、授权、链接、商用许可和关键词管理。
3. 素材匹配优先级：手工指定 > 本地匹配 > AI 图片 > AI 视频 > 在线素材 > 文字模板。
4. 内容哈希缓存和局部失效。
5. 参数化模板接口与 `game-dev-log` 首个模板。
6. 可选 AI 图片 Provider；AI 视频不作为前置依赖。

验收：开发日志可优先复用用户素材，单个镜头可替换/重生成且其他镜头不变。

### M5：Electron 桌面封装

进度：已完成主进程、预加载脚本、单实例、安全上下文、用户工作区、桌面/渲染日志、打包运行时与 NSIS 配置；Windows 解包程序已完成打开项目、预览服务和真实 MP4 导出验收，安装包已重新生成。自动更新、日志导出 UI 和 macOS 兼容列入后续增强。

任务：

1. Electron 主进程、预加载脚本与上下文隔离。
2. 白名单 IPC：文件选择、项目读写、媒体探测、渲染任务。
3. FFmpeg/字体/渲染运行时的打包策略。
4. Windows 首发安装包；macOS 路径与打包兼容验证。
5. 崩溃恢复、日志导出、更新策略和卸载数据说明。

验收：新设备安装后，可打开 demo-project、预览并导出视频。

## 4. 建议迭代节奏

以 1 周迭代为例：

- 第 1 周：M0 与 M1.1～M1.3。
- 第 2 周：M1.4～M1.7。
- 第 3 周：demo、命令、真实渲染、修复与 MVP 发布。
- 第 4～5 周：M2 编辑体验。
- 第 6～7 周：M3 脚本、TTS 与字幕对齐。
- 第 8 周：M4 最小素材库和首个模板。
- 第 9 周以后：根据真实使用反馈决定 Electron 与更多 AI 能力的优先级。

这是单人开发的建议区间，实际排期以每个里程碑退出条件为准，不以日期强行结项。

## 5. 优先级任务清单

### P0：必须完成

- 工程基线。
- 项目 Schema、加载和验证。
- 图片/视频镜头、字幕、基础动效和淡入淡出。
- 旁白音频与静音降级。
- 浏览器预览和真实 MP4 导出。
- demo-project、测试和使用说明。

### P1：形成生产效率

- 镜头卡片编辑器。
- AI 脚本/分镜、TTS 和时间对齐。
- 词级字幕、缓存和局部重试。
- 本地素材库与 `game-dev-log` 模板。

### P2：扩展产品形态

- Electron、更多平台预设和衍生文件导出。
- AI 图片/视频、在线素材、自动发布等可选能力。

## 6. 风险与应对

| 风险             | 影响                 | 应对                                 |
| ---------------- | -------------------- | ------------------------------------ |
| 一次开发过多模块 | 功能多但主链路不可用 | M1 前禁止引入 AI 与 Electron         |
| 音画时长不一致   | 字幕或镜头错位       | 基于音频真实时长和转录时间戳校准     |
| 跨平台媒体差异   | 本机可用、换机失败   | 统一路径层、启动检测、真实打包测试   |
| AI 输出不稳定    | 项目数据损坏         | 严格 JSON、Zod、修复上限、人工可编辑 |
| 渲染耗时和费用   | 迭代效率下降         | 哈希缓存、局部失效、低清预览         |
| 素材版权不清     | 无法安全发布         | 本地优先并强制保存授权元数据         |
| 时间轴需求膨胀   | 偏离自动生产核心     | 首版固定镜头卡片和简化时间条         |

## 7. MVP 发布检查表

- [ ] 全新环境可按 README 安装并启动。
- [ ] demo-project Schema 与素材校验通过。
- [ ] 图片、视频、三种布局和五种动效正确。
- [ ] 字幕未越出安全区，淡入和描边/阴影正常。
- [ ] 有/无旁白两条路径均可运行。
- [ ] 淡入淡出无黑帧、重叠或尾帧错误。
- [ ] 实际 MP4 编码、分辨率、帧率和音频符合要求。
- [ ] 类型检查、测试和 lint 全部通过。
- [ ] 错误信息包含字段路径或镜头 ID。
- [ ] 已记录未实现功能，未将 P1/P2 描述为已完成。

## 8. 第一轮 Codex 实施任务

第一轮只执行 M0 和 M1，目标是从 `project.json` 到真实 MP4。明确排除 AI API、Electron、账号/云端、素材搜索、自动发布及复杂时间轴。完成后再按 M2～M5 分别下发独立任务，并在每轮要求测试、类型检查、lint、真实渲染和文档更新。

## 9. M6：科普视频导演与多镜头素材工作流（进行中）

第一阶段已完成多视觉镜头 Schema、素材策略、搜索词、生成提示词、缺失素材状态、工作台镜头计划和视觉质量分析。第二阶段已实现旁白段内多镜头渲染、实际素材类型识别、视频源片段裁剪，以及棱镜色散、太阳光进入大气层和瑞利散射三类科普动画；90 秒“为什么天空是蓝色”视觉草稿已真实导出。下一阶段接入素材候选检索与确认，用真实天空视频替换缺失素材，并优化科普专用字幕和品牌模板。

## 10. M7～M9 路线

### M7：AI 素材生产闭环

图片/视频/图生视频 Provider、异步任务、2～4 个候选、单镜头选择与重试、版本保留、生成文件入素材库并进入最终时间轴。

进度：已完成多项目入口、文案/脚本/分镜总览、候选版本和任务状态模型、本地图片/视频候选、OpenAI `gpt-image-2` 竖屏图片草稿、Sora 图生视频异步任务、生成文件落盘及素材库登记。选中视频候选后会自动回填当前镜头和场景。下一步补充任务队列恢复、并发限制与费用预估。

验收：一个镜头完成“提示词 → 图片候选 → 选择 → 图生视频 → 自动剪辑”。

### M8：参考视频分析

本地视频和直接链接导入、转录、场景切分、关键帧、叙事结构、镜头节奏、字幕和声音分析，输出风格档案并用于新主题。

验收：分析“为什么天空是蓝色”，以其抽象结构生成“为什么夕阳是红色”的导演方案。

### M9：完整 AI 导演

自动研究、Provider 选择、预算控制、批量镜头生成、质量审核、失败降级、数字人以及多平台输出。
