# AI 科普短视频视觉素材工作流

## 1. 背景与问题

科普短视频已经可以较低成本地完成选题、文案、配音和基础剪辑，但“每段旁白应该对应什么画面”仍是主要瓶颈：

- 文生视频和图生视频成本较高，不适合覆盖全部镜头。
- 网络素材搜索结果不稳定，逐条预览、筛选和切片耗时。
- 同类科普内容会重复使用人物情绪、人体结构、自然现象、科技物体等视觉元素。
- 只按项目保存素材会造成重复下载、重复生成和跨项目复用困难。

因此，产品方向应从“尽可能生成视频”调整为“理解视觉意图，优先复用素材，以最低成本补齐画面缺口”。

## 2. 推荐生产流程

```text
选题与文案
→ 视觉意图拆解
→ 自动匹配公共素材和项目素材
→ 图片动态化或科普动画模板
→ 搜索外部素材
→ 仅对关键缺口生成图片或视频
→ 自动组装
→ 人工审核和替换
```

60 秒科普视频建议拆成 8～15 个视觉信息单元，每个镜头约 3～8 秒。不要为了追求节奏机械拆成大量镜头。

## 3. 画面表达策略

系统为每个分镜推荐成本最低且表达准确的方案：

1. **真实素材**：适合人物、地点、历史事件、真实实验和事实证据。
2. **静态素材动态化**：使用推近、拉远、平移、景深、局部放大、遮罩和视差等效果。
3. **模板化科普动画**：适合 DNA、细胞、神经、气味传播、光线折射、数据对比等高频概念。
4. **AI 生成素材**：只补充稀缺、难搜索或对叙事特别关键的镜头。

文生视频、图生视频、项目分类素材和网络搜索等现有能力继续保留，但从默认路径调整为素材缺口的补充手段。

## 4. 双层素材库架构

### 4.1 公共素材库

公共素材库独立于任何项目，用于长期积累和跨项目复用。

建议目录：

```text
cut-flow-library/
├─ library.json
├─ people/
├─ science/
├─ nature/
├─ technology/
├─ templates/
└─ thumbnails/
```

公共素材库应支持：

- 用户配置任意本地目录。
- 递归扫描图片、视频、音频和模板。
- 根据文件哈希去重，而不是只依赖文件名。
- 自动生成缩略图和基础媒体信息。
- 保存语义标签、版权、来源、比例、时长及适用主题。
- 目录整体复制到新电脑后，通过重新选择目录和扫描完成恢复。
- 元数据使用相对路径，避免盘符或绝对路径变化导致失效。

### 4.2 项目素材库

项目素材库继续保存在项目目录中，负责：

- 当前项目导入和下载的素材。
- AI 生成图片、视频及其提示词。
- 已使用素材的项目副本或引用快照。
- 分镜选择、截取范围、动画设置和历史版本。
- 保证项目在公共素材库不存在时仍可打开和重新导出。

### 4.3 两者关系

```text
公共素材库
   ↓ 匹配与预览
复制或固定引用到项目
   ↓
项目素材库
   ↓
分镜、时间线和最终成片
```

默认建议将公共素材复制到项目中。这样会增加少量磁盘占用，但可以保证项目可迁移、可归档、可复现。后续可增加“仅引用公共素材”模式，供高级用户节省空间。

## 5. 公共素材元数据

单个素材建议记录：

```json
{
  "id": "asset-uuid",
  "relativePath": "science/dna/dna-rotation.mp4",
  "hash": "sha256",
  "type": "video",
  "subject": ["DNA", "遗传"],
  "contentCategory": "科学解释",
  "applicableTopics": ["基因", "遗传", "疾病"],
  "emotion": ["理性", "神秘"],
  "width": 1080,
  "height": 1920,
  "duration": 6.2,
  "motion": ["旋转", "粒子流动"],
  "source": "generated",
  "license": "licensed",
  "commercialUse": true,
  "usageCount": 6
}
```

文件夹分类只用于人工浏览，自动匹配主要依赖结构化标签和向量语义，不应依赖目录名称。

## 6. 素材缺口分析

每个分镜应显示：

- 推荐表达方式。
- 已匹配的公共素材和项目素材。
- 匹配分数及推荐理由。
- 是否可通过图片动态化完成。
- 是否需要搜索或 AI 生成。
- 预计生成成本。
- 是否已经满足成片条件。

示例：

| 分镜         | 推荐方案     | 匹配结果       | 后续操作  |
| ------------ | ------------ | -------------- | --------- |
| 香菜叶片特写 | 图片动态化   | 公共库匹配 92% | 直接采用  |
| 喜欢与嫌弃   | 人物情绪拼接 | 公共库匹配 78% | 查看候选  |
| 气味进入鼻腔 | 科普动画模板 | 已匹配模板     | 调整颜色  |
| 基因差异     | DNA 通用资产 | 公共库匹配 88% | 直接采用  |
| 开场冲突     | AI 视频      | 无合适素材     | 生成 5 秒 |

## 7. 跨电脑恢复

推荐迁移步骤：

1. 复制整个公共素材库目录。
2. 在新电脑的设置中选择公共素材库目录。
3. 应用读取 `library.json` 并递归扫描实际文件。
4. 通过文件哈希修复移动或重命名后的路径。
5. 重新生成可丢弃的缩略图和搜索索引。
6. 显示缺失、重复和新增素材，用户确认后完成恢复。

API Key、Secret Key 等敏感配置不应放入公共素材库，也不随目录迁移。

## 8. 分阶段实施

### V1：可迁移公共素材库

- 设置公共素材库目录。
- 扫描、识别、去重和基础标签。
- 公共库/项目库切换筛选。
- 将公共素材复制到当前项目。
- 导出和恢复素材库索引。

### V2：自动匹配与缺口分析

- 根据分镜视觉意图匹配素材。
- 展示匹配度和推荐理由。
- 批量接受、替换或标记缺口。
- 图片动画效果自动推荐。

### V3：科普模板和语义引擎

- DNA、细胞、人体、自然现象等模板库。
- 语义向量检索和相似素材推荐。
- 素材复用率、使用次数和内容重复度控制。
- 根据成本和质量自动选择搜索、图片动态化或 AI 生成。

## 9. 产品原则

- 公共素材库负责积累和复用，项目素材库负责交付和复现。
- 保留现有素材分类、搜索、文生视频和图生视频能力。
- AI 生成是缺口补充，不是默认覆盖全部镜头。
- 自动匹配必须可解释、可替换，最终决定权属于用户。
- 项目不应因公共目录移动、素材删除或电脑更换而无法重新导出。
